# Timing test cartridge

Static test pages to photograph on a real Vectrex, to compare the emulator's analog timing (line
ends, corners) with the hardware. Button 4 switches pages.

| Page | What |
|---|---|
| SQUARES 08-17 | 16 squares drawn with the BIOS line routine (Draw_VLp, as Mine Storm uses), at scales (timer 1 lengths) $08..$17, labelled |
| LINES + END DOTS 08-17 | 16 horizontal lines at those scales; after each, a dot placed where the line should end (a beam move of the same vector, same scale): the gap between the line's lit end and the dot = its dark end |
| BOWTIES 08-17 | Robot Arena's flybot outline at those scales (one closed path) |
| SHIPS 0A-0D 5F / 7F | Mine Storm's ship (its own vector list, as Mine Storm draws it with Draw_VLp) at scales $0A-$0D; top row at Mine Storm's intensity $5F, bottom row $7F. Mine Storm draws it at $0C |
| BIG SHIPS 0A-0D 5F / 7F | the same with every vector doubled: twice the beam speed, the same timing, so the gaps are twice as wide (easier to photograph) |

Files: `timing_test.asm` (source, lwasm), `timing_test.bin` (32 KB), `timing_test_64k.bin` (the 32 KB
image twice, for a W27C512 on a PB6-switched cart: it boots in either bank). `roms\Timing Test.bin` is
the same for the emulator.

Photos: one per page, the whole screen in the frame, camera straight on, exposure short enough that
the lines are not blown out (the dots and gaps must stay visible). A close-up of each page's lower
half helps too.

Build: `lwasm --format=raw -o timing_test_raw.bin timing_test.asm`, then pad to 32768 bytes with $FF.

## Open bus test (`openbus_test.bin`)

One static page, **OPEN BUS READS**: each line reads an address no chip drives ($8000-$BFFF, the
$C000-$C7FF hole) with a different instruction and shows the byte in hex. On real hardware the
floating data bus decides the value; Mine Storm's split-mine bug (an object of type 4 gets a stray
vector list address, $3408) draws such bytes, so the emulator needs the real rule. The last line reads
$3408 inside this cartridge (the image is padded with $FF): how the cart maps its image there.

| Line | Read | Tells |
|---|---|---|
| LDA 9000 / 9055 / 90AA | extended | fixed value, or the last byte fetched ($00 / $55 / $AA)? |
| LDA C123 | extended, $C000-$C7FF | the other hole |
| LDA ,X 9000 | indexed (an idle cycle at $FFFF first) | does the idle cycle's BIOS byte ($00) show? |
| LDD 1,X HI / LO, LDB ,X+ | Draw_VLp's own reads | what the stray list really reads |
| LDA ,X C2E8 | where the emulated stray list walked | |
| LDA <00 DP90 | direct page | |
| LDA 3408 CART | inside this cartridge | the cart's padding / mirroring |

The emulator (2026-10-14): FF FF FF 00 FF FF FF FF 00 FF FF. Files: `openbus_test.asm`,
`openbus_test.bin` (32 KB), `openbus_test_64k.bin` (twice, for the 64 KB EPROM), `roms\Open Bus Test.bin`.

## CPU timing test (`cputime_test.bin`)

One static page, measured once at power-on, shown as 4 rows of 8 hex values (no labels: few
characters keep the BIOS text at 50 Hz). Generated by `make_cputime_test.py` (delays built
cycle-exact from NOP = 2 and BRN = 3).

Rows A and B: cycles of 6809 instructions, timed with timer 2 (a routine with the instruction minus an
empty one). Datasheet = emulator = the owner's Vectrex (first photo, 2026-10-14):

| A | NOP 02 | MUL 0B | PSHS+PULS 10 bytes 1E | LDA ,X 04 | LDA 1,X 05 | LDA ,X+ 06 | LDA [,X] 07 | LDA D,X 08 |
|---|---|---|---|---|---|---|---|---|
| **B** | LDA A,X 05 | LBRA 05 | CLRA+LBEQ taken 08 | LDA #1+LBEQ not taken 07 | JSR+RTS 0D | EXG 08 | TFR 06 | LEAX 1,X 05 |

Rows C and D: raw VIA readings; `off` = cycles from the end of the starting write to the read's last
cycle. Emulator values in brackets:

| C | T1 counter ($40) right after start [3C] | 2 cycles later [3A] | T1 ($04) after running out [EC] | T1 ($10) flag off 16 [00] | off 17 [00] | off 18 [40] | off 19 [40] | PB7 (T1 = the ramp switch) off 17 [00] |
|---|---|---|---|---|---|---|---|---|
| **D** | PB7 off 18 [80] | PB7 off 19 [80] | shift register flag after writing $FF, off 13 [00] | off 14 [00] | off 15 [04] | off 16 [04] | off 17 [04] | off 18 [04] |

The owner's Vectrex (2026-10-14): A and B as above; C 3C 3A **04** 00 00 40 40 00; D 80 80 00 00 **00 00**
04 04. The emulator then had EC (timer 1 kept counting down after running out; the 6522 reloads it from
the latch) and the shift register flag 2 cycles early: both fixed, the page now reads the same.

Files: `cputime_test.asm`, `cputime_test.bin` (32 KB), `cputime_test_64k.bin`, `roms\CPU Timing Test.bin`.

## Sample-and-hold test (`sh_test.bin`)

One page, generated by `make_sh_test.py`: the Y sample-and-hold's settling time. The DAC reaches the Y
integrator through a hold capacitor, connected while the multiplexer is on. Each dot: the hold is first
charged to a far value P (40 cycles), then set to the target T with the multiplexer on for only *d*
cycles (the number under the column: 4, 6, 7, 8, 9, 10, 12, 16, 24, 40), then the beam moves out and a
dot is drawn. Top row: P = -$7F, T = +$40; bottom row: P = +$7F, T = -$40. The short dim marks at both
ends of each row are the target height, drawn by the BIOS. A dot that falls short of the marks
(back towards P) did not settle in *d* cycles; how far short per *d* gives the hold's time constant. The emulator's hold is instant: all dots on the marks.

The owner's Vectrex (2026-10-14, 6 photos): only the d = 4 dot falls short, by ~1.5 DAC steps of the
191-step jump in both rows (0.8 %); from d = 6 the dots sit with the rest (the rows bow slightly toward
the screen's middle: the tube's geometry). The emulator now charges the hold 70 % of the gap per cycle
(VT_YSHK): d = 4 is 2 steps short, d >= 6 settled.

Files: `sh_test.asm`, `sh_test.bin` (32 KB), `sh_test_64k.bin`, `roms\S+H Test.bin`.

## Brightness test (`bright_test.bin`)

One page, generated by `make_bright_test.py`: 16 columns at intensity $02, $04, $08, $0C, $10, $18, $20,
$28, $30, $38, $40, $50, $60, $70, $78, $7F (dense at the low end, where the beam nears cutoff). Each
column: a vertical bar drawn with the BIOS line routine (the same length and speed for all), below it a
dot (the same resting time for all); the intensity in hex in two staggered rows at the bottom.
Photographed with a fixed exposure (manual: one setting for the whole series, the $7F bar not clipped),
the bars' and dots' brightness per intensity calibrates the emulator's brightness curve
(`vecrender.beam_z`): where the beam disappears, how fast it grows, where it saturates.

The owner's Vectrex (2026-10-14): counted by eye, 10 bars (the $20 one very faint) and 10 clear dots
(from $20); the photo (low exposure) peaks of the bars $28 / $30 / $38 / $40: 8 / 67 / 117 / 182 (from
$50 the camera clips). The emulator's curve below intensity 63 now has that cutoff (vecrender.beam_z /
beam_zdot) and shows the same 10 bars and 10 dots.

Files: `bright_test.asm`, `bright_test.bin` (32 KB), `bright_test_64k.bin`, `roms\Brightness Test.bin`.

## Wobble test (`wobble_50.bin`, `wobble_48.bin`, `wobble_25.bin`)

A still picture (two boxes and two lines of text) at a fixed frame rate, for the README's demonstration of
the mains hum wobble: the BIOS starts a frame every `Vec_Rfrsh` cycles, set here to 30,000 (50 fps, in
step with 50 Hz mains), 31,250 (48 fps: a game slightly over its budget - the picture sways) or 60,000
(25 fps: in step again). Built from `wobble_test.asm` with `-DREFRESH=n`, padded to 32 KB. (At 25 fps the
emulator's frame counter shows 50: it splits frames longer than 33,000 cycles in two.)

## FPS test (`fps_test.bin`, `fps_line.bin`)

A still picture whose frame rate changes every 128 frames, its name on screen: **50 FPS**, **40 FPS**, **30 FPS**,
**25 FPS**, **50/25 ALTERNATE**, **IRREGULAR** (frames of 20-43 ms), then again. On a real Vectrex the picture
keeps its brightness in every phase - only the mains wobble grows as the frame rate drops. `fps_test.bin` draws a
ring of boxes; `fps_line.bin` (built with `-DLINE`) one long horizontal line across the middle, to check a single
vector at every screen refresh. In the emulator: `roms\FPS Test.bin`, `roms\FPS Line Test.bin`.

Build: `lwasm --format=raw -o fps_test_raw.bin fps_test.asm` (add `-DLINE` for the line build), padded to 32 KB.
